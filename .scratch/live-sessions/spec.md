# 「進行中」即時 session 頁面

Status: ready-for-agent

## Problem Statement

我同時在終端機（Mac 上的 Ghostty、Windows 上的 Windows Terminal）開著好幾個 Claude Code 和 Codex CLI session，各自跑很久。時間一長就忘記每個 session 做到哪、哪一個正在等我回覆、該先回哪一個，要回去時還得在一堆分頁裡一個個找。已經關掉的 session 想接著做，也得自己去翻對話 id、切到原資料夾再手打指令。

Token 戰情室目前只回答「過去花了多少 token」，沒有「現在每個 agent 在做什麼」這個視角。

我曾經做過 Claude Code 的 mod 版本（session-board），但不想讓 Claude Code 載入額外的 mod、也不想改它的設定，所以改成在 Token 戰情室這個本機網站上做同樣的事，並且把 Codex 一併納入。

## Solution

在 Token 戰情室新增一個獨立頁面「進行中」（`/live.html`），首頁頂部加一個連結進入。

頁面上半部是**卡片牆**：每個還開著的 Claude Code 或 Codex CLI session 一張卡片，讓我一眼看到：

- 它叫什麼名字、在哪個資料夾；Codex 的卡片另外標出來
- 它現在的狀態：等你回覆、工作中、閒置（閒置只用左邊框的顏色表示）
- 目前的 context 有多大（最後一次送出的 token 數）
- 我最後下的指令是什麼
- 待辦進度（幾項做完、目前在做哪一項）
- 我多久以前下的指令（只顯示這一個時間，靠右放在卡片最後一行）

點一張卡片，直接跳到那個 session 所在的終端機分頁（macOS 的 Ghostty，或 Windows 上 WSL 的 Windows Terminal）。

頁面下半部是「最近結束」：24 小時內結束的 session（最多 10 筆），每張有「接續」按鈕，按下去會在終端機開新分頁、切到原資料夾、自動執行 `claude --resume <id>` 或 `codex resume <id>`。

閒置的 Claude Code 卡片可以改名：輸入新名稱後，看板把 `/rename 新名稱` 複製到剪貼簿並跳到那個分頁，由我自己按 Ctrl+V、Enter，改名由 Claude Code 執行，效果等同在 CLI 打 `/rename`。

「進行中」的卡片可以釘選：點 📌 後，那張卡片固定排在最前面，不再隨狀態變化跳位置；再點一次取消。釘選只記在這個瀏覽器裡。

整個功能只讀取本機既有的對話紀錄與 session 清單，不改 Claude Code 或 Codex 的任何設定、不裝 hook、不呼叫任何 AI 服務。網站預設只接受本機連線。

## User Stories

### 看現在有哪些 session

1. 身為同時開多個 agent 的開發者，我想在一個頁面看到所有還開著的 Claude Code session，以便不用在分頁間來回切換確認。
2. 身為同時開多個 agent 的開發者，我想在同一個頁面也看到所有還開著的 Codex CLI session，以便兩種工具一起掌握。
3. 身為開發者，我想在新開一個 session 後幾秒內就出現在頁面上，不必重新整理。
4. 身為開發者，我想在關掉一個 session 後它自動從「進行中」消失，以便清單只反映現況。
5. 身為開發者，我想讓 Codex 的卡片標出「Codex」，以便分辨；我幾乎只用 Claude Code，所以 Claude Code 的卡片不另外標示，每張都寫只是雜訊。
6. 身為開發者，我想看到每張卡片的 session 名稱，以便認出它；沒有名稱時顯示所在資料夾名稱。
7. 身為開發者，我想看到每張卡片所在的專案資料夾名稱，以便知道它在做哪個專案。
8. 身為開發者，我想在沒有任何 session 開著時看到「目前沒有進行中的 session」，而不是空白頁。
9. 身為開發者，我不想在清單裡看到 Claude Code 或 Codex 自己開出來的子 agent，以免畫面被塞滿。
10. 身為開發者，我不想在清單裡看到 VS Code 擴充套件或 Codex 桌面版的對話，因為我無法從這裡跳過去。
11. 身為開發者，我不想在清單裡看到 `claude -p` 這類背景執行的任務。

### 知道 agent 現在的狀態

12. 身為開發者，我想一眼看出哪些 session 正在工作中，以便知道不需要管它。
13. 身為開發者，我想一眼看出哪些 session 閒置、正等我下一個指令，以便優先處理。
14. 身為開發者，我想看到哪些 session 正在問我問題（選擇題或等我核准計畫），以便立刻回覆。
15. 身為開發者，我想讓「等你回覆」的卡片排在最前面、其次工作中、最後閒置；同一種狀態內最近有動靜的排前面。
16. 身為開發者，我想用不同顏色區分三種狀態，以便掃一眼就分得出來。
17. 身為開發者，我了解一般的權限確認框（Do you want to proceed?）目前偵測不到，那種情況會顯示成「工作中」；我接受這個限制，也不希望系統用猜的產生誤報。

### 知道做到哪

18. 身為開發者，我想在卡片上看到我最後下的指令，以便想起這個 session 在做什麼。
19. 身為開發者，我想看到我多久以前下的最後一個指令（例如「4m 前」），以便知道這個 session 放了多久。
20. 身為開發者，我想讓這個時間只有一個、不加標籤、靠右放在卡片最後一行，不要有其他時間混在一起。
21. 身為開發者，我想看到待辦進度條（完成幾項／共幾項）和目前正在做的那一項，以便知道長工作做到哪個階段。
22. 身為開發者，我想讓 Codex 的計畫（步驟與完成狀態）也顯示成同樣的進度條。
23. 身為開發者，我不想在卡片上看到 Bash 或其他工具動作的即時文字，因為那只是雜訊。
24. 身為開發者，我想讓「最後指令」只算我自己打的字，不要把工具回傳結果、系統通知或指令輸出算進去。
25. 身為開發者，我想在對話很長、最後指令已經捲出紀錄尾端時，仍然能顯示正確的最後指令與時間。
26. 身為開發者，我想讓頁面每 3 秒自動更新，並在我切到別的瀏覽器分頁時暫停更新，以免白白耗資源。

### 跳回去

27. 身為開發者，我想點一張卡片就跳到那個 session 所在的終端機分頁（Ghostty 或 Windows Terminal），以便馬上回去處理。
28. 身為開發者，我想在找不到對應分頁時看到「找不到這個 session 的分頁」，而不是系統默默開一個新的。
29. 身為開發者，我想在同一資料夾有好幾個分頁符合時，系統跳到第一個，而不是報錯。
30. 身為開發者，我想讓系統在跳轉時比對「資料夾 ＋ 分頁標題」：Claude Code 的分頁標題結尾是 session 名稱，Codex 的分頁標題開頭是對話名稱。
31. 身為開發者，我想在同資料夾開了兩個 Codex 時，仍能正確對到各自的對話。

### 接續已結束的 session

32. 身為開發者，我想在頁面下方看到 24 小時內結束的 session（最多 10 筆、最新的在前），以便接著做。
33. 身為開發者，我想在每一筆看到名稱、資料夾、我最後的指令與結束時間。
34. 身為開發者，我想按「接續」後，系統在終端機（Ghostty 或 Windows Terminal）開新分頁、切到原資料夾、自動執行 `claude --resume <id>` 或 `codex resume <id>`。
35. 身為開發者，我想讓接續開出來的分頁在 agent 結束後仍留著一般的 shell，不會直接關掉。
36. 身為開發者，我想在按接續時不用再多一次確認視窗，因為安全性已經由系統保證。
37. 身為開發者，我不想對還開著的 session 提供「接續」，因為兩個程式同時寫同一份對話紀錄會出問題。

### 安全

38. 身為使用者，我想讓網站預設只接受本機（127.0.0.1）連線，以免同一個 Wi-Fi 的其他人看到我的對話內容。
39. 身為使用者，我想讓「跳到分頁」和「接續」只接受來自看板自己頁面的 POST 請求，其他網站發出的請求一律拒絕，以免我瀏覽惡意網頁時被偷偷觸發。
40. 身為使用者，我想讓系統只能執行固定的兩種指令（`claude --resume <id>`、`codex resume <id>`），而且 id 必須是看板目前已知的 session，不接受任何自訂指令或自訂資料夾。
41. 身為使用者，我想讓系統絕不讀取 Claude Code session 清單資料夾裡的 `.key` 金鑰檔。

### 維護

42. 身為 fork 的維護者，我想讓新功能放在新檔案裡、對原本程式只做最少的修改，以便之後合併原作者的更新不容易衝突。
43. 身為 fork 的維護者，我想讓新功能不依賴資料庫結構，以便原作者改資料庫時不會影響到它。

### 改名

44. 身為開發者，我想在看板上替進行中的 Claude Code session 改名，效果等同在 CLI 打 `/rename`：卡片名稱、分頁標題與 `--resume` 清單一起變。
45. 身為開發者，我想讓看板只負責複製指令並帶我到分頁，最後由我自己貼上、按 Enter，因為看板看不到輸入框裡有沒有草稿或開著的選單，代替我按下去可能把草稿送給 agent 或核准權限。
46. 身為開發者，我想在 session 工作中或等我回覆時不能改名，並看到原因，以免把指令貼進問題的回答欄或權限框。
47. 身為開發者，我想在名稱不合格時（空白、超過 200 字、有換行或看不見的字元、以反斜線結尾）立刻看到原因，而不是貼上後才發現指令卡在輸入框。
48. 身為開發者，我想讓「最近結束」裡沒取名的 session 顯示 Claude 自動產生的標題，而不是「yes」「/exit」這類最後指令。

### 釘選

49. 身為開發者，我想把正在盯的幾個 session 釘在「進行中」最前面，因為卡片依狀態排序、每 3 秒重排，狀態一變我就得重新找它們。
50. 身為開發者，我想讓釘住的卡片依釘選先後固定排列、不跟著狀態或時間跳，連沒釘的「等你回覆」也排在它們後面。
51. 身為開發者，我想在釘住的 session 結束後按「接續」時，它帶著釘選回到原本的位置，不必重釘。
52. 身為開發者，我想讓已經找不到的 session 的釘選自動清掉，不必自己整理。

### 卡片內容

53. 身為開發者，我想在卡片上看到目前的 context 有多大，以便看出哪個 session 每一輪花得多、快要被壓縮，該考慮重開。
54. 身為開發者，我不想在最後一行看到對話被壓縮時 Claude Code 自動寫的摘要（This session is being continued…），那不是我打的字。
55. 身為開發者，我不想同一個 session 出現兩張一樣的卡片（例如以 Ctrl+Z 暫停後，又在同一個分頁接續）。
56. 身為開發者，我想讓閒置的卡片不寫「閒置」兩個字、最後一行不出現 `[Image #2]` 這種佔位字，讓卡片只留有用的資訊，標題也比較常一行放得下。

## Implementation Decisions

### 範圍與定位

- 只給自己用：支援 macOS 的 Ghostty，以及 Windows 上以 WSL 執行時的 Windows Terminal；介面只做繁體中文，不做其他語言，也不更新 README 與 CHANGELOG。
- 不送任何東西回原作者。`upstream` 只用來拉更新。
- 第一版不做 Haiku 摘要（目標／階段／下一步）；留到第二版。
- 即時狀態不存進資料庫，每次請求即時讀取、即時回傳。

### 資料來源與判斷「還開著」

**Claude Code**
- 還開著的 session 清單來自 Claude Code 自己維護的 session 登記資料夾：每個執行中的 Claude Code 一個 JSON 檔，含程序 id、session id、資料夾、名稱、狀態（busy／idle／shell）、更新時間。該資料夾尊重 `CLAUDE_DIR` 覆寫。
- 該資料夾內的 `.key` 檔是機密，任何情況都不得開啟、讀取或列出內容。
- 每筆都要再確認程序還活著；已死掉的登記檔視為已結束，不顯示在「進行中」。
- 名稱與分頁標題一致：對話紀錄的 custom-title（自己取的名字）優先，沒有就用 ai-title（Claude Code 自動產生的標題），都沒有才用登記檔的 name。沒取名時，登記檔的 name 是「資料夾-代號」形式的自動代號（nameSource 為 derived），對不上分頁標題。兩種標題紀錄會反覆寫入且彼此交錯，所以不能取「最後一筆標題」。
- 狀態對應：busy 與 shell 顯示「工作中」，idle 顯示「閒置」；若對話紀錄顯示有 AskUserQuestion 或 ExitPlanMode 的呼叫還沒有收到對應結果，則顯示「等你回覆」，且優先於登記檔的狀態。
- 對話紀錄位置：專案資料夾下以「工作資料夾路徑中非英數字元換成連字號」命名的子資料夾，檔名為 session id。

**Codex**
- Codex 沒有 session 登記資料夾。「還開著」要從終端機裡執行的 `codex` 程序反推：只算有終端機的 Codex 互動介面程序，排除 app-server 常駐程序與 VS Code 擴充套件的程序。
- 注意：Codex 互動介面程序本身不會開啟對話紀錄檔，常駐程序才會。所以不能用「程序開啟的檔案」來對應，要用下面的規則。
- 程序對應到對話的規則（依序）：(1) 啟動參數帶有對話 id 就直接用；(2) 否則只看終端機版（originator 為 codex-tui）的對話，且同資料夾只有一個對話時取它；(3) 同資料夾有多個對話時（不論有幾個程序），向 Ghostty 取分頁標題，挑出標題為「名稱 | 資料夾」的對話（名稱後面要接分隔符號，「fix」不能對到「fix login」），最多取程序數量個；讀不到標題或沒有相符時，只顯示最近更新的一個。這樣即使從清單接續了舊對話，也會跟著它的分頁而不是最新的對話。
- 對話的資料夾、名稱、紀錄檔位置、來源類型（使用者或子 agent）、更新時間，來自 Codex 的本機狀態資料庫。該資料庫是 WAL 模式，必須以一般唯讀方式開啟才看得到最新資料；immutable 會漏掉尚未合併進主檔的變更（實測少了約 2 小時的資料），只在一般唯讀開不了時才退而使用。只收來源為使用者的對話，排除子 agent。尊重 `CODEX_DIR` 覆寫。
- 工作中／閒置：最後一個「回合開始」之後沒有「回合完成」或「回合中止」就是工作中，否則閒置。
- 等你回覆：只偵測 Codex 主動詢問使用者（request_user_input_async）而我還沒回答的情況。這個問題工具是非同步的：呼叫後立刻就有「已接受」的回傳，Codex 之後可能繼續做事，我的答案則以一般的使用者訊息出現，所以不能用「等到工具結果」判斷，而是「最後一次提問之後我還沒再打字」；而且只有回合已結束（閒置）時才算等你回覆，Codex 還在做事時仍顯示工作中。Codex 的權限確認不會寫進紀錄，偵測不到。

### 對話紀錄尾端解析

- 只讀對話紀錄檔的最後一段（約 400 KB），因為紀錄檔可能超過數 MB；第一行可能被截斷，必須略過解析失敗的行。
- 從尾端取出：最後一個使用者指令與其時間、待辦進度、是否在等使用者回覆、最後一次送出的 context 大小。
- 「使用者指令」只算人打的字：排除工具回傳結果、標示為 meta 的訊息、對話被壓縮後 Claude Code 以使用者訊息寫進紀錄的摘要（`isCompactSummary`）、背景任務通知、本機指令輸出。人自己輸入的 shell 指令與斜線指令算人打的。Codex 的使用者訊息要排除系統注入的內容（例如環境資訊、AGENTS 指示）。
- 貼圖時 Claude Code 會在文字裡留下 `[Image #2]` 這種佔位字，顯示前拿掉；拿掉後沒有文字、只有圖片時顯示「（圖片）」。只拿掉「#」後面接數字的，其餘方括號是人自己打的字。
- 若尾端範圍內找不到使用者指令，要回頭掃描整份檔案找最後一個。
- Claude Code 的待辦進度來自最後一次 TodoWrite；Codex 的進度來自最後一次 update_plan（參數是 JSON 字串，含步驟與 pending／in_progress／completed 狀態）。進度 = 完成數／總數，加上目前進行中那一項的文字。
- 解析結果以「檔案大小＋修改時間」為鍵在記憶體中快取，避免每 3 秒重讀未變動的檔案。

### 最近結束

- 條件：最後活動在 24 小時內、目前不在「進行中」、不是背景執行（Claude Code 紀錄中標示為 sdk-cli 的）、不是子 agent、Codex 只算終端機版。
  - Codex 的「終端機版」以對話的 originator 為 codex-tui 判斷：來源欄位不可靠（終端機接續 VS Code 建立的對話時仍記為 vscode）。
  - 重開同一段對話（例如 resume 或 /clear 之後）會換一個 session id，舊的紀錄仍在：若進行中的 session 與它的標題、資料夾都相同，就視為同一段，不重複列出。
- 最多 10 筆，最近的在前。每筆含名稱（取對話的自訂標題，沒有就取 ai-title，再沒有就取最後指令開頭）、資料夾、最後指令、結束時間（以最後活動時間為準）。

### 跳到分頁

- 透過 Ghostty 的 AppleScript 介面，遍歷所有視窗、分頁、終端機，比對「工作資料夾」與「標題」後呼叫 focus。
- Claude Code：資料夾相同，且標題以 session 名稱結尾（標題前面有狀態符號）；session 沒有名稱時只比對資料夾。
- Codex：資料夾相同，且標題開頭是對話名稱（標題格式為「對話名稱 | 資料夾名稱」）。
- 多個符合就取第一個；沒有符合就回傳「找不到」，**不得**自動接續或開新分頁。
- Ghostty 回報不支援（沒有 osascript，或 osascript 執行失敗）時，改試 Windows Terminal；不偵測作業系統，macOS 的行為不變。
- Windows Terminal：以 powershell.exe 執行 UI Automation 腳本（`-EncodedCommand`），列出第一個視窗的分頁標題；找到後執行 `wt.exe -w 0 focus-tab -t <序號>`，再把視窗帶到最前面（先送一個 Alt 鍵事件，否則 Windows 不讓背景程式搶前景）。
  - Windows Terminal 不提供分頁的工作資料夾，只能比對標題，所以規則比 Ghostty 嚴格：Claude Code 的標題在狀態符號之後必須剛好是 session 名稱（「fix」不能對到「◐ hotfix」，也不能對到 Codex 分頁「x | fix」）；Codex 同樣要求「對話名稱 | 」開頭。沒有名稱的 session 回傳「找不到」。
  - 只看第一個視窗（UI Automation 依疊放順序列出）。
- 兩種終端機都不能用、或找到分頁但 `wt.exe` 執行失敗時，回傳明確的「不支援」訊息；終端機沒開時回傳「找不到」，不報內部錯誤。

### 接續

- 在最前面的 Ghostty 視窗開新分頁（沒有視窗就開新視窗），以 Ghostty 的「初始工作資料夾」設定資料夾，並以「初始輸入」把指令打進 shell，使 agent 結束後分頁仍保有一般 shell。資料夾不放進輸入的文字裡。
- 輸入文字只允許兩種固定形式：`claude --resume <id>`、`codex resume <id>`。
- 請求只帶「哪個 agent」與「id」；資料夾由伺服器依 id 自己查，絕不接受請求端傳來的資料夾或指令文字。id 必須先通過格式檢查（UUID），且必須是看板目前清單上已知的 session。
- 對「進行中」的 session 不提供接續。
- Ghostty 開不了時改用 Windows Terminal：`wt.exe -w 0 new-tab wsl.exe --cd <資料夾> -- bash -lic "<接續指令> || true && exec bash"`。資料夾是 wsl.exe 的參數、不進指令文字；以 `|| true &&` 串接而不用 `;`，因為 wt.exe 會把 `;` 當成下一個 wt 指令的開頭。資料夾名稱含有 `;`、`"` 或 `\` 時拒絕：`;` 等於能夾帶任意 wt 指令，`"` 與 `\` 會破壞 Windows 命令列的引號處理。只有 PATH 裡找得到 wt.exe 時才做這項檢查；沒有 wt.exe（例如 macOS 上 Ghostty 開不了）時回一般的「不支援」訊息。

### 改名

- 半自動：網頁驗證名稱、把 `/rename 新名稱`（不含換行）複製到剪貼簿，並呼叫既有的 `POST /api/live/focus` 跳到分頁；由我在分頁按 Ctrl+V、Enter。伺服器不新增 API，網頁不往 agent 輸入任何文字，「只讀取既有紀錄」的原則不變。
- 不做全自動的原因：外部改登記檔或對話紀錄會被執行中的 Claude 寫回舊名，分頁標題也只有它自己能設；官方的 session 訊息通道不執行斜線指令；WSL 核心關閉了 TIOCSTI；Windows Terminal 沒有從外部送字的方法（只能搶焦點後模擬按鍵）；Ghostty 雖有 `input text`，但兩個平台都讀不到輸入框內容，有草稿時會把「草稿＋指令」當訊息送出，權限框開著時 Enter 等於核准。
- 只有進行中、狀態為閒置的 Claude Code 卡片有可用的 ✎；工作中與等你回覆時停用並說明原因。Codex 沒有對應的 `/rename`，不顯示；「最近結束」不提供改名。
- 名稱規則：去掉頭尾空白；1～200 字（Claude Code 的上限）；不允許換行、控制字元與看不見的格式字元；不能以反斜線結尾（反斜線加 Enter 會變成換行）。
- 以 `<dialog>` 輸入、預填目前名稱：卡片每 3 秒整張重畫，就地編輯會被清掉。
- 剪貼簿寫入失敗時，在對話框顯示並選取指令讓我手動複製；跳轉失敗仍算複製成功，提示請自己切過去貼上。

### 釘選

- 只有「進行中」的卡片可以釘，Claude Code 與 Codex 都可以；「最近結束」不能釘，也不顯示釘選標記（本來就依結束時間排、24 小時內最多 10 筆）。
- 卡片標題列最右邊放 📌（Claude Code 卡片在 ✎ 右邊），點一下切換釘選，不觸發跳轉。釘住的卡片 📌 亮著、外框加強調色；沒釘的 📌 淡色。不加分隔線或「已釘選」標題。
- 排序：釘住的卡片一律排在最前面，依釘選先後排列（先釘的在上，新釘的接在釘選區最後），不看狀態與時間；張數不設上限、不做拖曳。沒釘的卡片照後端的排序。取消釘選後卡片回到一般排序的位置，其他釘選卡片的順序不變。
- 識別：以 `agent:id` 記錄。`claude --resume <id>` 預設沿用原本的 session id（另加 `--fork-session` 才會換），`codex resume <id>` 也延續同一段對話，所以接續後釘選仍對得上；`/clear` 會換 id，釘選隨之失效，需要重釘。
- 保留與清除：釘住的 session 只要還出現在「進行中」或「最近結束」任一份清單就保留釘選，兩份都找不到才清掉。只在成功取得 `GET /api/live` 時清理，連線失敗不會清空釘選；兩份清單都是空的時候也不清，因為後端讀取失敗時同樣回傳空清單。
- 存在瀏覽器的 localStorage，後端不新增 API：只有一個人在本機用，跨瀏覽器同步不值得多一支寫入端點。每次使用前重新讀取，兩個分頁同時開著也不會互相蓋掉；localStorage 不能用（例如被瀏覽器擋掉）時，釘選只在這次瀏覽有效。

### 卡片內容

- 副標依序是：資料夾（有標題時才放，沒有標題時標題本身就是資料夾）、「Codex」（只標 Codex，Claude Code 不標）、context 大小，以「 · 」分隔。「最近結束」同樣只標 Codex。
- 狀態文字：等你回覆與工作中顯示「● 狀態」；閒置是預設狀態，畫面上只用左邊框的顏色，文字以視覺隱藏的方式留給螢幕閱讀器，卡片的提示文字也寫出狀態。
- context 大小：Claude Code 取最後一則主對話（不含子 agent）助理回覆的 `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`，三者加總為 0 的回覆（中斷時補上的訊息，沒有真的呼叫模型）略過。Codex 取最後一筆 `token_count` 的 `last_token_usage.input_tokens`（已含快取的部分），`info` 是 null 的略過。只在「進行中」顯示，還沒有回覆時不顯示。
- context 的格式：`context 121K`，千位取整數；999,500 起寫成一位小數的 M（例如 `1.2M`），避免四捨五入出「1000K」。一律灰色、不設門檻，滑鼠停留時說明「最後一次送出的 context 大小」。Claude Code 的紀錄沒有 context 上限，門檻只能用猜的；Codex 雖有 `model_context_window`，為了兩邊一致也不算百分比。
- 同一個 `agent:id` 有多個程序時只回一筆，取登記檔更新時間最新的那個（正在用的），跳轉也照它的資料找分頁。實際碰過的情況：在同一個分頁以 Ctrl+Z 暫停 `claude`，再 `claude --resume` 同一個 id，暫停中的程序 `kill(pid, 0)` 一樣會成功，兩筆登記都算還開著。
- 刻意不放上卡片：模型與權限模式（各 session 幾乎都一樣）；git 分支（紀錄的是整個資料夾當時所在的分支，同一個資料夾的 session 會顯示同一個，容易誤以為是那個 session 自己的分支）；壓縮次數（要每次掃整份紀錄）；recap 的翻譯（Claude Code 有時用英文寫，翻譯要呼叫模型）。

### HTTP 介面

- `GET /api/live`：回傳「進行中」與「最近結束」兩份清單，已排序、狀態已判斷好；前端只負責畫。
- `POST /api/live/focus`：請求內容為 agent 與 id。
- `POST /api/live/resume`：請求內容為 agent 與 id。
- `GET /api/live` 的內容含我打過的指令與資料夾，所以 Host 也必須是本機位址（localhost、127.0.0.1、[::1]），否則回 403；這擋掉 DNS rebinding 的網頁讀取。
- 兩個 POST 都必須：請求的來源（Origin）等於伺服器自己的位址、內容類型為 JSON；缺少或不符一律拒絕。
- 預設綁定位址從 `0.0.0.0` 改為 `127.0.0.1`；仍可用 `HOST` 環境變數覆寫。這是對上游行為的刻意偏離。
- 原本的 `/sync` 等既有端點不在此次修改範圍。

### 前端

- 新增獨立頁面 `/live.html`，附屬的腳本與樣式也是獨立檔案；既有的大型腳本與首頁只做最小修改（首頁頂部加「進行中」連結）。
- 沿用既有看板的配色與深淺主題；卡片依視窗寬度自動排成多欄。
- 文字直接寫繁體中文，不走既有的多語系機制（避免動到五種語言的大檔）。
- 每 3 秒輪詢 `GET /api/live`；頁面不可見時暫停。
- 所有從紀錄解析出來的欄位（名稱、指令、資料夾）都視為不可信輸入，輸出到畫面前一律跳脫，以防注入。

### 開發規範（沿用原作者）

- 提交前：`cargo fmt --check`、`cargo test --locked`、release 建置零警告、`cargo clippy --all-targets --all-features -- -D warnings`、`npm test`、`git diff --check`。
- 前端改動要在另一個 port 以真實資料啟動，截圖確認深色、淺色與窄螢幕。
- commit 訊息沿用原作者的格式（繁體中文 Conventional Commits）。
- 程式碼審查使用 `/mattpocock-skills:code-review`。

## Testing Decisions

- **好測試的標準**：只測外部可觀察的行為，不測內部實作細節。
- **唯一的接縫**：新功能的 HTTP API，對真正編好的程式測試。沿用既有整合測試的做法：啟動程式、指到暫存資料夾（`INSIGHTS_DIR`、`CLAUDE_DIR`、`CODEX_DIR`）、寫入假的對話紀錄檔與 session 登記檔、以 HTTP 呼叫並檢查回傳 JSON。
- **假的系統指令**：把假的 `ps`、`lsof`、`osascript`（Windows Terminal 的測試另加 `powershell.exe`、`wt.exe`）小腳本放在 PATH 最前面（預設都回報「沒有」，測試才不會碰到這台電腦真正的程序與 Ghostty）。腳本依劇本回答「哪些程序在跑」，並把收到的參數記錄成檔案，讓測試斷言「會對 Ghostty 下什麼指令」。不得為了測試在正式程式碼加專用開關。Claude Code 的存活判斷同樣要能在測試裡被控制（例如以假指令，或以測試程序自己的 pid 當作活著、以已結束的 pid 當作已死）。
- **Codex 狀態資料庫**：測試以暫存的假資料庫提供，內容含對話的資料夾、名稱、紀錄檔位置、來源類型、更新時間。
- **要涵蓋的行為**：
  - Claude 與 Codex 各自「還開著／已死」的判斷，包含同資料夾多個 Codex 的對應
  - 三種狀態與優先順序（等你回覆 > 工作中 > 閒置）、排序
  - 最後指令與時間：只算人打的字；紀錄被截斷的第一行；指令在尾端範圍之外時的回頭掃描
  - 待辦／計畫進度的計算與目前項目
  - 「最近結束」的篩選：24 小時、最多 10 筆、排除背景執行與子 agent
  - 跳轉：產生的分頁比對條件；多個符合取第一個；沒有符合時回傳「找不到」且不開新分頁
  - 接續：產生的指令只有兩種固定形式；未知 id、格式錯誤的 id、進行中的 session 一律拒絕；請求帶了自訂資料夾或指令時被忽略或拒絕
  - 安全：來源不符、缺少來源、內容類型不是 JSON 的 POST 被拒絕；預設綁定位址為本機
- **既有範例**：`tests/additional_sources.rs`（TestServer、寫假的 jsonl、reqwest 呼叫）。
- **不放進自動測試**：頁面外觀（以截圖手動確認）與實際的 Ghostty／Windows Terminal 跳轉（假腳本只能驗證會下什麼指令，真正跳過去、視窗帶到前景要手動試一次）。讀分頁的腳本各留一個預設忽略、要在真實終端機裡才能跑的測試：`cargo test -- --ignored real_ghostty`、`cargo test -- --ignored real_windows_terminal`。
- 解析邏輯先不另外加單元測試層；若實作時發現某個邊界情況透過 HTTP 接縫太難測，再補。
- 改名的名稱驗證是純前端邏輯：`static/rename-utils.js` 的 `renameCommand`，比照既有的前端工具以 `npm test` 測試。對話框、剪貼簿、跳轉與 ✎ 的停用規則以瀏覽器手動確認（攔下 POST，避免切換真正的分頁）。
- 釘選的排序、切換與清理是純前端邏輯：`static/pin-utils.js`，比照 `rename-utils.js` 以 `npm test` 測試。📌 的外觀、點擊不觸發跳轉、重新整理後保留與 localStorage 失效時的行為以瀏覽器手動確認。
- 卡片內容：壓縮摘要不算指令、圖片佔位字、context 大小（Claude Code 與 Codex）、重複程序合併，都透過 HTTP 接縫測試；context 的顯示格式是純前端邏輯（`static/context-utils.js`），以 `npm test` 測試。閒置字樣、副標與窄螢幕以假資料截圖確認（PR 是公開的，真實資料的畫面會露出工作上的 session 名稱）。

## Out of Scope

- Haiku 摘要（目標／階段／下一步）：第二版。
- 在網頁上輸入文字、直接交給 agent 執行（例如背景跑 `claude -p --resume`）：會與開著的終端機搶同一份對話紀錄，也等於開了遠端執行的門。
- 偵測 Claude Code 與 Codex 的權限確認框：兩邊都無法從紀錄可靠判斷，也不做「工具呼叫太久就猜在等你」的猜測。
- Cursor、GitHub Copilot、Grok 等其他工具的即時狀態。
- Codex 在 VS Code 擴充套件與桌面版裡的對話，以及 Codex 的子 agent 對話。
- Linux，以及 Ghostty 與 Windows Terminal 以外的終端機；同時開多個 Windows Terminal 視窗；Windows Terminal 上依分頁標題區分同資料夾的多個 Codex（仍只有 Ghostty 支援）。
- 多語系介面、README 與 CHANGELOG 更新、發版。
- 全自動改名（模擬鍵盤、AppleScript 送字或直接改 Claude Code 的檔案）；Codex 與「最近結束」的改名。
- 釘選的拖曳排序、跨瀏覽器同步，以及「最近結束」的釘選。
- 卡片上的模型、權限模式、git 分支與壓縮次數；context 大小的變色提醒與百分比；recap 的翻譯。
- 鍵盤快捷鍵（1–9 跳轉）、桌面通知。
- 把即時狀態存進資料庫、歷史分析。
- 修改原本的 `/sync` 等端點的安全性。
- 送 PR 回原作者。

## Further Notes

- **名詞**：「進行中」＝程序還活著的 session；「最近結束」＝24 小時內已結束的 session；「接續」＝以該 agent 的 resume 指令重開舊對話。專案目前沒有 `CONTEXT.md`。
- **前身**：同樣的需求曾做成 Claude Code 的 mod（session-board），已移除。那次踩過的坑已寫進上面的決定：紀錄檔超過 4 MiB 要讀尾端、最後指令可能在尾端範圍之外、人打的 shell 指令與斜線指令要算人打的。
- **Ghostty 分頁標題格式**：Claude Code 是「狀態符號 ＋ session 名稱」；Codex 是「對話名稱 | 資料夾名稱」，由 Codex 設定檔中終端機標題的選項控制，若改了該設定，比對規則會失效。
- **上游同步**：本規格寫於上游 v1.5.0（2026-10-23）之上。新功能需要碰既有檔案的地方只有三處：路由註冊、首頁的連結、預設綁定位址。
- **風險**：`GET /api/live` 與兩個 POST 都要求 Host 是本機位址，所以即使用 `HOST` 把網站改綁到非本機位址，也只能用 localhost 或 127.0.0.1 這類名稱連進來讀取；區網用法不在這次範圍。
- **AppleScript 的坑**：在 Ghostty 的 `tell` 區塊裡，`tab` 指的是它的 tab 類別，會被轉成「tab」這個字而不是定位字元；分隔符號要在區塊外先定義。假的 osascript 測不出這種問題，所以保留一個要真的 Ghostty 才能跑的測試：`cargo test -- --ignored real_ghostty`。
- **程式碼審查**：`/mattpocock-skills:code-review` 的發現已處理，細節見 commit 訊息；刻意不做的是把 agent 與 status 改成 enum（目前只有兩種 agent，之後有第三種再做）。Windows Terminal 那一輪（Standards 8 項、Spec 5 項）全部處理：兩個行為問題見 commit c84c7d2，結構與註解見 e8f2815，規格文字見本檔。
- **終端機的程式結構**：`terminal` 模組放兩種終端機共用的型別與「先 Ghostty、再 Windows Terminal」的切換順序；`ghostty`、`windows_terminal` 各自只處理自己那一種。
- **工作單拆分建議**：先做 Claude Code 的清單與卡片（含跳轉），再加 Codex，最後做「最近結束」與接續，每一段都能獨立驗證。
